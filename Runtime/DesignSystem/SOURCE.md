### Behaviour on Unity 6000.3

`ThemeRuntime`'s comments (upstream) say a theme added last to the same element as the base tokens wins ties by sheet order. Measured on 6000.3.25f1 with `.ds-root { background-color: var(--fdp-color-bg) }` under a document:

| Base sheet on | Theme on | Painted |
|---|---|---|
| document root | document root | base (dark): theme loses, in either sheet order |
| a child of the document root (a UXML `<Style>`) | document root | base: theme loses |
| panel root (`root.parent`) | document root | theme (light) |
| document root | a child of the root | theme |
| panel root | panel root | base |

So the theme must sit on a descendant of the element holding the base sheet. The UIKit facade (`UIKitInstaller`) does this, the showcase sample does this, and the DesignSystem test `ThemePanelTests` documents it. Upstream code and guides are unchanged; whether newer Unity versions behave differently is untested here.

## Package dependencies

From the upstream manifest and the module's code, only two built-in modules are required, and both are listed in this package's `package.json` `dependencies`:

- `com.unity.modules.unitywebrequest`: the runtime Google Fonts fetcher (`DsGoogleFonts`, behind the `DS_WEBREQUEST` define) and the editor font importer use `UnityWebRequest` (the editor code is not guarded, so it is required).
- `com.unity.modules.vectorgraphics`: the SVG importer. Without it the 120 icons do not import as textures and every `.ds-icon--*` rule would resolve to nothing.

Not required: uGUI, the Input System, URP, Addressables, TextMeshPro. UI Toolkit itself and TextCore are part of the default engine modules. (The upstream manifest lists uGUI, the Input System and URP only for its showcase project.)

## Unity version guards

Upstream already guards what needs a newer Unity; nothing was added.

- `UNITY_6000_5_OR_NEWER`: the whole GPU material pipeline (all eight files in `Runtime/DesignSystem/Fx/`, and `Editor/DesignSystem/Fx/DsFxCompileCheck.cs`), the PanelRenderer variants of the applier and behaviour, and the `EntityId` overload of `OnOpenAsset` in `ThemeConfiguratorWindow`. On 6000.0 to 6000.4 these compile out and the module works without material skins (USS theming, icons, components, typography are unaffected).
- `UNITY_6000_4_OR_NEWER`: the `FindObjectsByType` overload in `DesignSystemBehaviourBase`.
- `DS_WEBREQUEST` (asmdef `versionDefines` on `com.unity.modules.unitywebrequest`): `DsGoogleFonts`.
- `DsFxBlueprint.shader` is a plain shader in Resources and is NOT version-guarded; it is only used by the 6000.5+ pipeline. Static check against 6000.3.25f1's `CGIncludes/Internal/UnityUIE.cginc`: every `uie_*` / `UIE_*` symbol that `DsFx.cginc` uses exists there. Verified in the integration run: the shader imports with no compiler messages on 6000.3.25f1 (an EditMode test checks it).
- Runtime assembly has one `#if UNITY_EDITOR` block (`[UnityEditor.InitializeOnLoadMethod]` in `DsFxBlueprintFamily.cs`), inside the 6000.5 guard. Nothing else in `FutureDigitalPlus.UIKit.DesignSystem` touches `UnityEditor`.

## Third-party data check (asked for by the notices)

- Theme palettes: the six bundled theme assets are generated by `ThemePresets.GenerateBatch` from `Theme/Palette/ThemePalettes.cs`. `Dark` started from the hex values written by the upstream author (`ThemePresets.cs`, mirroring `DesignTokens.uss`) and was changed for contrast; `Light` was changed likewise; `HighContrast*` are computed from them (`ThemeDerivation.HighContrast`); `Neutral*` are new. The greys of `NeutralDark` and `NeutralLight`, and most of their accent hues, are the hex values of the Tailwind CSS default palette (zinc, blue, purple, red, green, amber). Colour values are facts, not code, and nothing of Tailwind's code or CSS is in the package; this is noted for transparency. The third-party Codigrate palettes are only in the excluded Showcase folder.
- Fonts: none bundled (see Excluded).
- Network behaviour (only when the feature is invoked, never at import or startup): `DsGoogleFonts` (runtime) fetches from `https://raw.githubusercontent.com/google/fonts/main/`; the editor Google Fonts window reads `https://fonts.google.com/metadata/fonts` and `https://api.github.com/repos/google/fonts/git/trees/main`. Fonts fetched this way carry their own licences (mostly SIL OFL); the game that imports them is responsible for that notice.
- The GitHub README has no per-asset attribution for the 120 SVG icons other than the MIT statement above.
