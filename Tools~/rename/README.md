# Rename tooling

The four upstream projects use generic names (`DesignSystem.Runtime`, `UIComponents`, `Game.UI`, `id.instance.elementanimationtoolkit`,
Resources folders such as `Textures/Icons`, USS variables such as `--color-bg`). In a game that merges several packages these
collide. `rename.py` is the deterministic function that turned the upstream trees into this package's names. It was applied once; it
stays here so an upstream update can be pushed through the same function before it is merged (`Documentation~/Upgrading.md`,
"Re-syncing after the rename").

| File | What |
|---|---|
| `rename.py` | The script. Python 3.9+, standard library only, no network. |
| `rename-map.md` | The mapping tables, generated by `python3 rename.py --dump-map`. |

## Scheme

| Kind | Rule |
|---|---|
| Assembly | `FutureDigitalPlus.UIKit.<Module>[.Editor]`; tests `FutureDigitalPlus.UIKit.<Module>.Tests[.Editor]` |
| Namespace | `FutureDigitalPlus.UIKit.<Module>[.X]` (the `.Runtime` level of the design system is dropped) |
| Resources | `FutureDigitalPlus/UIKit/<Module>/{Styles,Themes,Icons,Shaders}`; tests `.../Tests/...`; samples `.../Samples/...`; fonts `.../Fonts` |
| USS custom property | `--<name>` becomes `--fdp-<name>` (derived from the files: declarations, `var()` uses, C# literals, baked theme sheets) |
| USS class | Extras classes (`tooltip`, `color-field`, ...) become `fdp-*`; `.back-btn*` becomes `.ds-back-btn*`; `is-spinning` becomes `ds-is-spinning`; `mobile` becomes `fdp-input-touch` |
| Strings | menus under `FDP UI Kit` (`MenuItem`, `AddComponentMenu`, `CreateAssetMenu`, and sentences such as `Design System > Google Fonts` in C#, USS, and docs), the shader name `Hidden/FutureDigitalPlus/UIKit/DsFx/Blueprint`, the EditorPrefs key, `Assets/_FutureDigitalPlusUIKitTemp` |

## Use

Always on a copy first. `--apply` refuses the package that holds the script unless `--allow-live`; a dry run and `--verify-only` never write.

```
python3 rename.py --root <copy> --report r.json            # dry run (default): prints the plan, writes nothing
python3 rename.py --root <copy> --apply --report r.json    # apply: moves, asmdef, text, records, then verify
python3 rename.py --root <copy> --verify-only               # only the checks; exit code 1 on problems
python3 rename.py --dump-map > rename-map.md                # the mapping tables
```

Stages (idempotent: a second `--apply` changes nothing): **moves** (Resources content with its `.meta`, so GUIDs stay),
**asmdef** (name, `rootNamespace`, references, file and `.meta` name), **text** (cs, uss, uxml, tss, asmdef, rsp, shader, cginc, md,
and the two baked theme assets), **records** (a generated "Rename record" in each module's `SOURCE.md`), **verify** (asmdef
references resolve, no stale old name, every `--fdp-*` that is used is declared, every theme token is defined in `DesignTokens.uss`,
Resources literals resolve). Files that are never rewritten: licences, `THIRD_PARTY_NOTICES.md`, `CHANGELOG.md`, `package.json`,
`SOURCE.md` (except the record), the upstream README copies, `Samples~/Extras/BlurUrpLegacy~`, the NSubstitute folder, and the code and guides written after the rename (the new modules, the facade, their tests, samples and guides, listed in `VERBATIM_GLOBS`): they are already in the new names, and the old-name rules would misread a class suffix such as `UssClassName + "--empty"` or a game-owned example token such as `--mygame-color-health`. A comment line or a
Markdown line that says "upstream" documents upstream's names on purpose: it is left alone and listed as a review item.
Every C# file the script changes in upstream-derived code gets the first line `// FutureDigitalPlus: renamed by Tools~/rename/rename.py ...`.

Options: `--components rename|assemblies|keep` (default `rename`; `assemblies` renames the Components assemblies but keeps the namespace
`UIComponents`, which works with upstream's stock DLLs; `keep` renames nothing of Components), `--auto-ref keep|facade` (`facade`
sets `autoReferenced: false` on every assembly except the facade).

## What the script does not do (done by hand, recorded in the module `SOURCE.md` tables)

- The auto-attach define: upstream's always-on `RegisterAutoAttach` is wrapped in `#if FDP_UIKIT_AUTO_ATTACH` (opt-in).
- `package.json` (`unity` floor `6000.3`), `README.md`, `CHANGELOG.md`, `THIRD_PARTY_NOTICES.md` and the guides' prose that describes upstream.
- The two new tests that guard the token rename, and the test path edits in `Tests/`, which the script makes mechanically.
- The metas of the new `Resources/FutureDigitalPlus/...` folders (Unity generates them; keep them).

## Rebuilding the Components generator DLLs

Upstream's DLLs find types by the literal name `UIComponents.<X>`; in a renamed namespace they generate nothing and report nothing.
`rename.py --generator-src` copies the upstream `UIComponents.Roslyn` source, patches the string literals, renames the four assemblies and builds them:

```
python3 rename.py --generator-src <uicomponents clone>/UIComponents.Roslyn --generator-out <dir> --roslyn 4.0.1 --nuget-source ~/.nuget/packages
python3 rename.py --root <package> --apply --install-generator <dir>/dll      # copies DLL + PDB, derives each .meta (labels kept, deterministic new GUID)
```

The rebuild also applies one fix that is not a rename (`AugmentGenerationContext.GetTypeName` never shortens a framework type by the usings of the component's file, see `Runtime/Components/SOURCE.md`); the script stops if upstream changed that method.

`--roslyn 4.0.1` is the version available in the offline NuGet cache of the build machine (upstream pins 3.8.0; use that, without
`--nuget-source`, where NuGet is reachable). Record the upstream commit, the Roslyn version and the SHA-256 of the DLLs in
`THIRD_PARTY_NOTICES.md` each time. Acceptance: the Components tests pass (generated code exists), `[Query]` fields are filled, a
`readonly` `[Query]` field gives `UIC003`, and the `-analyzer:` lines appear in the `.rsp` of the Components assembly and its dependents only.

## Names that were deliberately kept

1. Type names of upstream code (`Easy`, `Easing`, `Tooltip`, `ILogger`, `Scope`, `Expander`, ...): the namespace removes the ambiguity, and renaming types would make every upstream diff expensive.
2. `ds-*` classes, `is-*` state classes chained to `ds-*`, `unity-*` classes and Animation's camelCase classes: scoped by prefix or by the stylesheet they are attached with.
3. `--unity-*` and `--ds-font-*` custom properties (the latter are written by the font importer and already prefixed).
4. Inside the rebuilt DLLs: internal namespaces `UIComponents.Roslyn.*`, the generated global `internal static class UIComponentAssetRegistry` and the `UIC_*` generated method names (found by literal name by `ConventionValidator`).
5. The shader global `_DsFxTime` and the include `DsFx.cginc`.
6. Assembly-local defines `DS_WEBREQUEST`, `UICOMPONENTS_ADDRESSABLES_INSTALLED`, `DS_UIR_STAGING_PATCHED`.
7. The upstream licence texts, README and CHANGELOG copies; `SOURCE.md` text outside the record.
8. The product name "UIComponents" in prose and links, and the folder name `PupupPanel` (upstream's typo).
